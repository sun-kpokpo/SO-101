# SO-101 : pick & place with ACT

Goal: teach the SO-101 follower to pick an object and place it in a tray, using **ACT** and a **single top camera**.

- Data recording + inference: this laptop (no NVIDIA GPU → inference on CPU)
- Training: NVIDIA A6000 machine

LeRobot source: `~/lerobot` (editable install). Everything below runs in the `lerobot` conda env:

```bash
conda activate lerobot
```

> The repo's `.venv` / `uv run` is **not** set up on this laptop — use the conda env.

## Hardware

| Arm | Controller board serial | Port (stable path) | Calibration id |
|---|---|---|---|
| Follower | `5A4B048489` | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5A4B048489-if00` | `my_follower_arm` |
| Leader | `5A4B047977` | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5A4B047977-if00` | `my_leader_arm` |

- Board `5A4B047947` is **defective** (USB keeps disconnecting) — don't use it.
- Use the `/dev/serial/by-id/...` paths, not `/dev/ttyACM0/1`: the ACM numbers depend on plug-in order, the by-id path follows the board's serial number.
- The by-id path belongs to the **board**, not the arm. If you swap boards, swap the paths. Motor IDs and calibration live in the motors / calibration files, not the board.
- Power: DC — **respect polarity** (+ to +, − to −) on the screw terminals. Reversed = nothing lights up.
- Follower power supply is **5 V 4 A (20 W)**: borderline for 6 STS3215 — fast moves or the start-up jump can make all motors drop out (`There is no status packet` on ids 1–6). A 5 V **8–10 A** supply fixes it.
- Top camera: **Logitech Brio 100**, recorded at 640×480 @ 30 fps — `/dev/v4l/by-id/usb-046d_Brio_100_2415AP0MU0J8-video-index0`. (The Orbbec depth camera from the Yahboom MUTO RS also works over OpenCV for RGB, but only reaches 30 fps at 640×480 and is not used.)

Calibration files:

```
~/.cache/huggingface/lerobot/calibration/robots/so_follower/my_follower_arm.json
~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/my_leader_arm.json
```

Shell shortcuts (optional, paste in the terminal or add to `~/.bashrc`):

```bash
export FOLLOWER_PORT=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5A4B048489-if00
```

## 1. Quick health check (read-only)

Plug both boards (USB + power), then:

```bash
python ~/SO-101/scripts/check_arms.py
```

Expect 6 motors (IDs 1–6) per arm. Put both arms in the same pose: joint differences should be a few degrees.
Don't run it while teleop/record is running (two programs on one port garble each other).

## 2. Teleoperate

Put both arms in the **same pose** first (rest pose is easiest) — the follower jumps to the leader's pose on start.

```bash
lerobot-teleoperate \
  --robot.type=so101_follower --robot.port=$FOLLOWER_PORT --robot.id=my_follower_arm \
  --teleop.type=so101_leader --teleop.port=$LEADER_PORT --teleop.id=my_leader_arm \
  --robot.max_relative_target=10
```

`max_relative_target=10` caps each follower step to 10° (safety). Stop with Ctrl+C (**never Ctrl+Z**: it pauses the program and keeps the ports locked).

### With the top camera + live view (recommended): `teleop_view.py`

Rerun is too heavy for this laptop, so this script does the same teleop loop (30 Hz) and shows the camera in a lightweight ffplay window:

```bash
python ~/SO-101/scripts/teleop_view.py
python ~/SO-101/scripts/teleop_view.py --save-reference ~/SO-101/reference.png   # save the last frame on exit (framing reference)
python ~/SO-101/scripts/teleop_view.py --overlay ~/SO-101/reference.png          # blend the reference over the live view to re-align the camera
```

### Rerun live view — does NOT work on this laptop

Rerun freezes on this laptop's AMD graphics (native viewer with Vulkan or OpenGL, and the web viewer
in Firefox), and drags the control loop down from 60 Hz to ~20 Hz. Use `teleop_view.py` above instead.

## 3. Top camera: check, view, set up

Camera: Logitech Brio 100, recorded at **640×480 @ 30 fps**, path `$TOP_CAM`. Only **one program at a time**
can use it: close teleop / `lerobot-record` / ffplay before running another.

**Check + live view, no arms needed** (`camera_check.py`):

```bash
python ~/SO-101/scripts/camera_check.py --list                              # which cameras are plugged
python ~/SO-101/scripts/camera_check.py                                     # checks resolution / fps / brightness, then live view
python ~/SO-101/scripts/camera_check.py --grid                              # + 3x3 grid to centre the workspace
python ~/SO-101/scripts/camera_check.py --overlay ~/SO-101/reference.png    # re-align: blend the reference over the live view
python ~/SO-101/scripts/camera_check.py --save ~/SO-101/reference.png       # save the last frame as the new reference
```

Expect `640x480, ~30 fps`. A very dark image (`brightness < 20`) = the Brio's **privacy shutter is closed**.

**Live view while teleoperating** (to check the arm's reach stays in frame): `teleop_view.py` (section 2).

**Setting up the camera:**

1. Top-down view. In frame: the gripper over the **whole object zone** and the **whole tray zone**, with margin
   (~3–4 cm) to the image edges. The arm's base can be just out of view (top edge).
2. Leader arm, your hands and other moving things **out of frame**. Even lighting, no strong shadows.
3. Mount it rigidly and **don't move it once recording started** — the policy learned that exact view.
4. Reference: `~/SO-101/reference.png` (first frame of the dataset). Also note the camera's height and position
   relative to the follower's base.
5. At a new place (demo): run with `--overlay ~/SO-101/reference.png` and move the camera / arm / taped zones
   until the live image lines up with the reference.

Plain ffplay preview (if the script isn't available):

```bash
ffplay -f v4l2 -input_format mjpeg -video_size 640x480 -framerate 30 $TOP_CAM
```

## Redo setup from scratch (only if needed)

### Find a board's port

With a single board plugged in: `ls -l /dev/serial/by-id/`.
With several: `lerobot-find-port` (unplug the board's USB when asked, *then* press Enter).

### Set motor IDs (once per arm, motors connected one at a time)

```bash
lerobot-setup-motors --robot.type=so101_follower --robot.port=$FOLLOWER_PORT
lerobot-setup-motors --teleop.type=so101_leader  --teleop.port=$LEADER_PORT
```

Starts with the gripper (id 6) down to the base (id 1). For each prompt, only that motor is connected to the board. Board power must be on.

Joint ↔ motor ID:

| ID | Name | EN | FR |
|---|---|---|---|
| 1 | `shoulder_pan` | Base rotation | Rotation de la base |
| 2 | `shoulder_lift` | Shoulder lift | Élévation de l'épaule |
| 3 | `elbow_flex` | Elbow | Coude |
| 4 | `wrist_flex` | Wrist flex | Flexion du poignet |
| 5 | `wrist_roll` | Wrist roll | Rotation du poignet |
| 6 | `gripper` | Gripper | Pince |

Leader gear ratios: 1 → 1/191, 2 → 1/345, 3 → 1/191, 4/5/6 → 1/147. Follower: all 1/345.

### Calibrate

```bash
lerobot-calibrate --robot.type=so101_follower --robot.port=$FOLLOWER_PORT --robot.id=my_follower_arm
lerobot-calibrate --teleop.type=so101_leader  --teleop.port=$LEADER_PORT  --teleop.id=my_leader_arm
```

1. If asked about an existing file: type `c` + Enter to recalibrate (plain Enter reuses the old file).
2. Middle pose: base centered, upper arm vertical, forearm horizontal, wrist straight, gripper half open, **wrist roll with the moving claw on top**. Enter.
3. Move every joint (except wrist roll) slowly to both end stops. Enter.

Keep the same `id` in every later command — it's how LeRobot finds the calibration.

## Troubleshooting (what we hit)

| Symptom | Cause / fix |
|---|---|
| `There is no status packet` on **all** ids 1–6 at once (often on a fast move or at start-up) | Follower power supply too weak (5 V 4 A): voltage dips, motors reset. Move calmly, start with both arms in the same pose; real fix = 5 V 8–10 A supply. |
| `There is no status packet` / missing motor IDs from N upward | A 3-pin cable in the chain came loose (we had it between motor 2 and 3 when sweeping the arm). Reseat it, leave slack so it doesn't pull when joints bend. Check: motors after the break have their LED off. |
| `Input/output error`, `device disconnected`, `error -71` in `sudo dmesg -w` | USB board dropping out. Check cable / port; if it persists with a known-good cable and port, the board is defective. |
| Board LED off, motors dark, but 5 V measured at the PSU | Power wires reversed on the screw terminals. |
| Follower wrist roll keeps spinning / does a full turn | Wrist roll near the ±180° wrap. Fixed by recentering wrist roll so claw-on-top = 0° on both arms. Avoid by having the claw on top during calibration. |
| Follower joint weak / gives up under load | Check for leftover torque limits from previous use (`Max_Torque_Limit`, `Protection_Current`, `Overload_Torque`). Only the follower's gripper should be reduced (500/250/25); others 1000/500/80. The follower's shoulder_lift had to be restored. |
| Elbow lags ~4° when lifting the forearm | Normal: gravity + deliberately soft motor gain (P=16). |
| Motor LEDs blinking | Motor error: overload (joint forced past its limit) or wrong supply voltage. |
| Port / camera busy, program won't start | A previous program is still running (or paused with Ctrl+Z, state `T`). Find it: `pgrep -af "lerobot-\|teleop_view\|ffplay"` · `fuser -v /dev/ttyACM*`. Stop it: `kill -INT <PID>` (if state `T`: `kill -CONT <PID>` first). |
| Camera image black | Brio 100 privacy shutter closed. |

## Recording the dataset

Dataset: `~/SO-101/datasets/so101_pick_place` (target: 100 episodes, tray and object placed randomly inside their taped zones).

```bash
lerobot-record \
  --robot.type=so101_follower --robot.port=$FOLLOWER_PORT --robot.id=my_follower_arm \
  --teleop.type=so101_leader --teleop.port=$LEADER_PORT --teleop.id=my_leader_arm \
  --robot.cameras="{ top: {type: opencv, index_or_path: $TOP_CAM, width: 640, height: 480, fps: 30}}" \
  --dataset.repo_id=local/so101_pick_place \
  --dataset.root=$HOME/SO-101/datasets/so101_pick_place \
  --dataset.single_task="Pick the object and place it in the tray" \
  --dataset.num_episodes=20 --dataset.episode_time_s=30 --dataset.reset_time_s=60 \
  --dataset.push_to_hub=false --resume=true
```

- `--resume=true` appends to the existing dataset; `num_episodes` = how many **more** to record this session. (Without `--resume`, an existing folder gives `FileExistsError`.)
- Keys (recording terminal must be focused): **→ / n** end episode or reset early · **← / r** redo episode · **Esc / q** stop.
- Each episode **starts** with the object at its start spot and the arm at rest; press → once the object is in the tray and the arm is back at rest.
- Open the gripper ~30–50 % before grasping. Move calmly (smoother demos, and no power dips).
- Keep the object and the tray **inside the camera view** (taped zones ~3–4 cm from the image edges).
- A crash only loses the episode in progress: rerun the same command (`--resume=true`).

Check the dataset after each session:

```bash
python ~/SO-101/scripts/dataset_health.py    # per-episode checks + contact sheets in ~/SO-101/health/
python ~/SO-101/scripts/coverage_map.py      # object/tray start positions on one image -> ~/SO-101/coverage_map.png
```

Delete bad episodes (writes the result to `~/.cache/huggingface/lerobot/local/so101_pick_place`, then swap folders, keeping the old one):

```bash
lerobot-edit-dataset --repo_id local/so101_pick_place --root ~/SO-101/datasets/so101_pick_place \
  --operation.type delete_episodes --operation.episode_indices "[2]"
```

## Training on the A6000

Everything for the training machine is in `~/SO-101/a6000/` (details in `SETUP_A6000.md`).
The dataset used for training is `so101_pick_place_clean` (54 episodes, bad ones removed). It is the default in all A6000 scripts.

**1. On the laptop, pack the dataset + the a6000 folder:**

```bash
DATASET=so101_pick_place_clean bash ~/SO-101/scripts/send_to_a6000.sh --tar   # -> ~/SO-101/so101_transfer.tar, copy it to the USB drive
DATASET=so101_pick_place_clean bash ~/SO-101/scripts/send_to_a6000.sh <user>@<a6000-ip>   # or over the network (SSH)
```

**2. On the A6000, unpack and install (once, about 10 min):**

```bash
tar -xf so101_transfer.tar -C ~                 # -> ~/SO-101/datasets/so101_pick_place_clean and ~/SO-101/a6000
bash ~/SO-101/a6000/install_a6000.sh
```

`install_a6000.sh` creates the conda env `lerobot` (python 3.12 + ffmpeg), installs LeRobot at commit `87db15c8` into `~/SO-101/lerobot`, pre-downloads the ResNet-18 weights, then runs `check_env.py`. It ends with 4 `[OK]` lines and "Ready to train." Safe to rerun. If an env called `lerobot` already exists that it did not create, it stops: rerun with `ENV_NAME=so101 bash ~/SO-101/a6000/install_a6000.sh`.

**3. Train:**

```bash
conda activate lerobot
bash ~/SO-101/a6000/train_act.sh                 # 50k steps, batch 32, checkpoint every 10k
STEPS=20000 bash ~/SO-101/a6000/train_act.sh     # shorter pilot run
```

Output: `~/SO-101/outputs/<run>/checkpoints/last/pretrained_model/`. Copy that folder back to the laptop in `~/SO-101/models/<run>/`.
